# ADR-003: Політика повної ізоляції даних для AI-модуля

## Статус
Прийнято

## Контекст
Система повинна генерувати персоналізовані рекомендації щодо навчальних планів за допомогою стороннього LLM API. Водночас необхідно суворо дотримуватися вимог приватності (НФВ-3) та уникати витоку персональних даних студентів.

## Рішення
Передавати стороннім LLM-провайдерам виключно анонімізований контекст: описи навчальних дисциплін та знеособлені побажання поточного користувача.

## Наслідки
- ✅ Повна відповідність вимогам політики конфіденційності та приватності
- ✅ Персональні дані, ID та корпоративні email-адреси студентів гарантовано залишаються в межах нашої інфраструктури
- ⚠️ Рекомендаційна модель спирається тільки на сухі описи курсів і безпосередні запити студента
- ❌ AI-модуль позбавлений можливості враховувати глобальний контекст (наприклад, реальний досвід, плани чи відгуки інших студентів) для покращення якості рекомендацій


## Розглянуті альтернативи

### 1. Передача повного профілю студента у LLM
Передача email, ідентифікаторів, планів минулих років та інших персональних даних для максимального контексту моделі.

**Причини відмови:**
- Використання стороннього LLM API означає, що персональні дані студента (email, ID, особиста історія) потрапляють до зовнішнього провайдера, де можуть зберігатися та потенційно витікати — пряме порушення вимог приватності (NFR-3)
- Персональні ідентифікатори не є значущими вхідними даними для генерації навчального плану: модель спирається на перелік доступних дисциплін та вподобання студента, а не на його особу
- Підвищує ризик регуляторних порушень (GDPR та внутрішня політика НаУКМА)

### 2. Self-hosted / on-premise LLM (наприклад, Llama через Ollama)
Розгортання відкритої моделі на власному сервері університету, де дані не виходять назовні.

**Причини відмови:**
- Значні накладні витрати на апаратне забезпечення та адміністрування власного LLM-сервера
- Оскільки вже прийнято рішення про модульний моноліт (ADR-001), запуск повноцінної LLM на тому ж сервері суттєво навантажить спільні ресурси та негативно вплине на продуктивність основного застосунку
- Використання готового стороннього API є значно простішим для команди та достатнім для потреб MVP
