# Документація проєктування API: YourPathUkma

## Огляд архітектури

- **Базова адреса:** `http://localhost:3000/api/v1`
- **Стиль API:** REST, JSON (`application/json`)
- **Технологія:** Python, FastAPI, Pydantic (підхід Code-First)
- **Автентифікація:** JWT Bearer-токени (Microsoft 365 SSO). *Статус: заглушка.* Зараз приймається будь-який непорожній токен, повна інтеграція SSO запланована.
- **Стратегія версіонування:** версія в шляху URL (`/api/v1`)
- **Документація:** Swagger UI `/api-docs`, ReDoc `/redoc`, специфікація генерується з коду у `docs/api/openapi-generated.yaml`

Архітектурно API належить до модуля **Core / Planning** модульного моноліту (ADR-001).

Повний контракт фронтенду і бекенду (зокрема запропоновані кінцеві точки для MVP і етапу 2, типи TypeScript): [`contract.md`](contract.md).

## Модель ресурсів

Нижче: що реалізовано в коді зараз, а що лише заплановано.

| Ресурс | Кінцева точка | Статус |
|---|---|---|
| IndividualPlan | `/plans` | реалізовано (заглушки) |
| Discipline | `/disciplines` | реалізовано (заглушки, лише читання) |
| Student, DeaneryPlanDocument, Direction, CertificateProgram | не визначено | заплановано |

### Ресурс IndividualPlan

- **Кінцева точка:** `/plans`
- **Опис:** індивідуальні плани вибіркових дисциплін студента на навчальний рік (створення, перегляд, редагування та видалення чернеток).

**Атрибути:**

| Поле | Тип | Опис |
|---|---|---|
| `id` | integer | унікальний ідентифікатор плану |
| `student_id` | integer | власник плану |
| `academic_year` | integer | навчальний рік, 2024–2030 |
| `course` | integer | курс, 2–4 (на 1 курсі план формує деканат, у застосунку його немає) |
| `load_levels` | object | навантаження по триместрах: `autumn`, `spring`, `summer`, кожне `low` / `medium` / `high` |
| `status` | enum | `draft` / `submitted` / `awaiting_deanery` / `approved` |
| `items` | array | вибіркові дисципліни плану (`PlanItem`) |
| `total_credits` | number | сумарні кредити ECTS (обчислюється) |
| `free_elective_credits` | number | кредити вільного вибору в плані (обчислюється) |
| `created_at` | datetime | дата створення |

**PlanItem:** `course_id`, `title`, `trimester` (1–3), `credits` (0–30), `is_free_elective`.

**Зв'язки:**
- належить одному Студенту (`Student`);
- містить багато Дисциплін (`PlanItem` → `Discipline`);
- пов'язаний з Документом деканату (`DeaneryPlanDocument`), *заплановано*.

### Ресурс Discipline

- **Кінцева точка:** `/disciplines`
- **Опис:** каталог дисциплін (дані з САЗ). Лише читання, наповнюється парсером.
- **Атрибути:** `id`, `title`, `description`, `discipline_type` (`normative` / `elective`), `instructor`, `recommended_year` (1–4), `trimester` (1–3), `credits`, `directions` (напрямки, для яких дисципліна профорієнтовна; порожній список означає вільний вибір).

## Перелік кінцевих точок і статус-кодів

Усі кінцеві точки вимагають заголовок `Authorization: Bearer <token>`.

| Метод | Шлях | Успіх | Помилки |
|---|---|---|---|
| POST | `/plans` | 201 Created | 401, 422 |
| GET | `/plans` | 200 OK | 401, 422 |
| GET | `/plans/{plan_id}` | 200 OK | 401, 403, 404, 422 |
| PUT | `/plans/{plan_id}` | 200 OK | 401, 403, 404, 409, 422 |
| DELETE | `/plans/{plan_id}` | 204 No Content | 401, 403, 404, 409, 422 |
| GET | `/disciplines` | 200 OK | 401, 422 |
| GET | `/disciplines/{discipline_id}` | 200 OK | 401, 404, 422 |

**Значення кодів:**
- **401:** немає або некоректний токен;
- **403:** план належить іншому студенту;
- **404:** ресурс не існує;
- **409:** дія неможлива в поточному статусі (редагувати й видаляти можна лише `draft`);
- **422:** вхідні дані не пройшли валідацію.

## Валідація вхідних даних

Валідація виконується на сервері (Pydantic), а не лише в UI.

- `academic_year`: 2024–2030; `course`: 2–4.
- `items`: від 1 до 30 дисциплін; `course_id` не повторюються.
- `trimester`: 1–3; `credits`: > 0 і ≤ 30; `title`: 2–150 символів.
- Кредити вільного вибору в плані ≤ 25 (ліміт за всі 4 роки).
- Не можна створити план, що складається лише з дисциплін вільного вибору.
- Параметри списків: `limit` 1–100, `offset` ≥ 0; `min_credits` не більше `max_credits`.
- *Заплановано:* перевірка сумарного ліміту вільного вибору за всі роки навчання та мінімуму 57–60 кредитів на рік (потрібні дані з БД та документа деканату).

## Проєктні рішення

### Чому Code-First?

Ми обрали підхід **Code-First (FastAPI + Pydantic)**, тому що:
1. Документація завжди збігається з реалізацією: схема OpenAPI генерується з Python-коду.
2. Типи Pydantic забезпечують автоматичну валідацію вхідних даних.
3. Швидші ітерації: не потрібно вручну підтримувати YAML/JSON-специфікацію.
4. Один стек із рештою бекенду та AI-модулем (Python).

### Стратегія пагінації

- **Тип:** `offset-based` (`limit` і `offset`), бо найпростіша для каталогу та списку планів.
- **Ліміт за замовчуванням:** 20; **максимальний:** 100.
- **Метадані відповіді:** `pagination` з полями `limit`, `offset`, `total`, `has_more`.

### Обробка помилок

Єдина машинозчитувана структура для всіх помилок 4xx/5xx, незалежно від джерела (бізнес-логіка, валідація, невідомий маршрут):

```json
{
  "code": "PLAN_NOT_FOUND",
  "message": "План з ID 5 не знайдено",
  "details": []
}
```

Для помилок валідації (422) `code = "VALIDATION_ERROR"`, а `details` містить елементи `{ "field": "items.0.credits", "message": "..." }` по кожному полю.

**Коди помилок:** `UNAUTHORIZED`, `PLAN_FORBIDDEN`, `PLAN_NOT_FOUND`, `PLAN_NOT_EDITABLE`, `PLAN_NOT_DELETABLE`, `DISCIPLINE_NOT_FOUND`, `VALIDATION_ERROR`, `INTERNAL_ERROR`, `HTTP_<код>` (технічні помилки маршрутизації).

### Вибір 422 для помилок валідації

Помилки валідації повертають **422 Unprocessable Entity**, а не 400: запит синтаксично коректний, але не відповідає правилам. Це стандартна поведінка FastAPI, тому не потрібні хаки в згенерованій специфікації, і код у документації збігається з реальним.

### Автентифікація та доступ

- Студент бачить і змінює лише власні плани, чужий план дає **403**.
- Каталог дисциплін доступний будь-якому автентифікованому студентові.
- Нормативні дисципліни (з документа деканату) доступні лише для читання.

### Версіонування

- Версія вказується в шляху: `/api/v1/...`.
- Нова мажорна версія (`/v2`) з'являється лише при **ламаючих змінах**: видалення або перейменування полів, зміна типів, зміна семантики статус-кодів.
- Додавання нових необов'язкових полів і нових кінцевих точок не потребує нової версії.
- Попередня версія підтримується мінімум один навчальний семестр після виходу нової; про застарівання повідомляємо заздалегідь.

### Заплановано (не входить у поточну реалізацію)

- `POST /plans/{plan_id}/submit`: перехід `draft` → `submitted`.
- Завантаження документа деканату та синхронізація із САЗ.
- AI-рекомендації та альтернативні плани.
- Реальна автентифікація Microsoft 365 SSO.
