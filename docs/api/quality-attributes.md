# Атрибути якості та матриця компромісів (Quality Attributes)

## П'ять атрибутів якості: Механізми та Метрики

Кожна ціль має вимірювану метрику та чітку умову провалу. Ціль, яку ніхто не вимірює — це побажання, а не вимога.

### 1. Зручність використання (Usability) — Пріоритет №1
| Параметр | Опис |
| :--- | :--- |
| **Ціль** | Забезпечити миттєвий зворотний зв'язок інтерфейсу та передбачуваний час роботи AI. |
| **Умова провалу** | <ul><li>p95 генерації AI-плану > 5 хвилин</li><li>Затримка UI (drag-and-drop) > 100 мс</li><li>Незрозумілі або неструктуровані повідомлення про помилку API</li></ul> |
| **Механізми** | <ul><li>Оптимістичне оновлення інтерфейсу (React-стан оновлюється до відповіді сервера)</li><li>Асинхронна обробка довготривалих AI-запитів із skeleton-завантажувачами</li><li>Узгоджена структура помилок API (обов'язкова наявність `request_id` та `message`)</li></ul> |
| **Вимірювання / Моніторинг** | <ul><li>**Lighthouse / RUM:** фіксація затримок інтерфейсу (Long Tasks > 50 мс)</li><li>**Серверні метрики:** логування часу виконання від звернення до LLM до відповіді</li></ul> |

### 2. Безпека та Приватність (Security)
| Параметр | Опис |
| :--- | :--- |
| **Ціль** | Абсолютна ізоляція PII від сторонніх сервісів та відсутність відомих вразливостей. |
| **Умова провалу** | <ul><li>Хоча б одна вразливість рівня High у звіті OWASP</li><li>Наявність email або ПІБ у логах вихідних запитів до LLM</li><li>Відповідь 5xx на невалідний вхід замість 400/422</li></ul> |
| **Механізми** | <ul><li>Валідація за схемами (Pydantic) на всіх endpoints</li><li>Анонімізація payload-у для AI ([ADR-003](decisions/ADR-003.md))</li><li>Обмеження швидкості (Rate Limiting: макс. 100 запитів/хв на користувача)</li><li>Автентифікація виключно через Microsoft 365 SSO</li></ul> |
| **Вимірювання / Моніторинг** | <ul><li>**OWASP ZAP:** автоматичне DAST-сканування у CI/CD</li><li>**Тести приватності:** E2E тести з перехопленням mock-запитів до LLM на наявність PII</li><li>**Аудит:** 100% покриття кінцевих точок перевіркою токена</li></ul> |

### 3. Надійність (Reliability & Data Integrity)
| Параметр | Опис |
| :--- | :--- |
| **Ціль** | Гарантована цілісність кредитних лімітів та висока доступність системи. |
| **Умова провалу** | <ul><li>Сумарний простій понад 43 хв на місяць (< 99.9% Uptime)</li><li>Можливість зберегти план, що перевищує 240 кредитів загалом або 25 вільного вибору</li><li>Потрапляння сирих, невідформатованих даних парсера в активний каталог</li></ul> |
| **Механізми** | <ul><li>ACID транзакції на рівні PostgreSQL ([ADR-001](decisions/ADR-001.md))</li><li>Буферизація та черга модерації для парсера САЗ ([ADR-002](decisions/ADR-002.md))</li><li>Повтори з експоненційним відступом (Retry with exponential backoff) для зовнішніх API</li><li>Кінцева точка `/health` для моніторингу життєздатності</li></ul> |
| **Вимірювання / Моніторинг** | <ul><li>**Uptime Robot:** пінг `/health` щохвилини</li><li>**Інтеграційні тести:** 100% покриття граничних умов лімітів (24, 25, 26 кредитів)</li></ul> |

### 4. Продуктивність (Performance)
| Параметр | Опис |
| :--- | :--- |
| **Ціль** | Швидке обслуговування базових операцій (каталог, профілі) для паралельних користувачів. |
| **Умова провалу** | <ul><li>p95 часу відповіді > 200 мс під час навантажувального тесту</li><li>Деградація часу відповіді при 50+ одночасних сесіях</li></ul> |
| **Механізми** | <ul><li>Пагінація (offset/limit) для об'ємних списків (каталог дисциплін)</li><li>Відсутність мережевих стрибків між бізнес-доменами завдяки Моноліту ([ADR-001](decisions/ADR-001.md))</li><li>Індексування часто запитуваних полів БД (назва, триместр, викладач)</li></ul> |
| **Вимірювання / Моніторинг** | <ul><li>**k6 / JMeter:** стрес-тест на 50 VUs (Virtual Users) протягом 5 хвилин</li><li>**APM:** трекінг повільних запитів до БД (> 50 мс)</li></ul> |

### 5. Підтримуваність (Maintainability)
| Параметр | Опис |
| :--- | :--- |
| **Ціль** | Гарантувати якість кодової бази, швидкий пошук помилок та швидку адаптацію нових розробників. |
| **Умова провалу** | <ul><li>Покриття коду тестами (Code Coverage) падає нижче 80%</li><li>Наявність порушень типізації (Mypy) або стилю (PEP8) у головній гілці</li><li>Внесення зворотньо несумісних змін (breaking changes) у працююче API без створення нової версії (напр., v2)</li><li>Неможливість знайти запит у логах за 15 хвилин через відсутність контексту</li></ul> |
| **Механізми** | <ul><li>Автоматичні лінтери (Ruff) та статичний аналіз типів (Mypy) на pre-commit хуках</li><li>Семантичне версіонування API (роутери з префіксами `/v1`, `/v2` у FastAPI)</li><li>Структуроване логування (JSON) з унікальним `correlation_id` для кожного запиту</li></ul> |
| **Вимірювання / Моніторинг** | <ul><li>**CI/CD Pipeline:** Pytest-cov блокує злиття, якщо покриття нижче 80%</li><li>**Linter Checks:** GitHub Actions падає при помилках Mypy/Ruff</li><li>**Contract Testing:** інструменти типу `openapi-diff` в CI/CD перевіряють Swagger і блокують PR, якщо зміна ламає існуючий контракт</li><li>**Log Analytics:** перевірка, що 100% транзакцій мають `correlation_id`</li></ul> |

## Аналіз компромісів (Trade-offs)

Кожен механізм має свою ціну: шифрування додає затримку, повтори подовжують відповідь, а розподіленість забирає простоту. У таблиці нижче наведено вибір, чим наш домен свідомо жертвує.

| Атрибут | Компроміс (Рішення) | Вплив | Пом'якшення |
| :--- | :--- | :--- | :--- |
| **Масштабованість** | Відмова від мікросервісів та Serverless на користь **Модульного моноліту** ([ADR-001](decisions/ADR-001.md)). | <ul><li>Обмежена здатність до горизонтального масштабування окремих вузлів</li><li>Спільне споживання ресурсів парсером і API</li></ul> | <ul><li>Аудиторія обмежена студентами факультету</li><li>Важкі задачі (напр. парсинг) виконуються вночі/у фоні</li></ul> |
| **Надійність** (Безпека каталогу) | Впровадження **Черги модерації** парсера ([ADR-002](decisions/ADR-002.md)) замість 100% авто-синхронізації. | <ul><li>Дані оновлюються із затримкою</li><li>Вимагає ручної праці адміністратора</li></ul> | <ul><li>Зручна адмін-панель для масового підтвердження (bulk approve)</li></ul> |
| **Приватність** (AI) | Повна ізоляція даних: відмова від передачі контексту інших студентів до LLM ([ADR-003](decisions/ADR-003.md)). | <ul><li>AI позбавлений колаборативного контексту (що зазвичай обирають інші)</li><li>Рекомендації можуть бути менш точними</li></ul> | <ul><li>Детальний промпт-інжиніринг на основі описів</li><li>Додання альтернативних варіантів дисциплін</li></ul> |
| **Зручність** (UX) | **"Живий пошук" (Search-as-you-type):** результати в каталозі дисциплін оновлюються миттєво під час введення тексту користувачем без натискання кнопки "Знайти". | <ul><li>Різке збільшення кількості HTTP-запитів та навантаження на базу даних (Full-text search), що знижує продуктивність.</li></ul> | <ul><li>Використання Debounce (штучна затримка 300-500 мс) на клієнті перед відправкою запиту; кешування результатів.</li></ul> |
| **Продуктивність** | Глибока валідація даних (Pydantic) та перевірка консистентності на кожному записі. | <ul><li>Додає ~20-50 мс затримки до кожного write-запиту</li></ul> | <ul><li>Індексування БД (PostgreSQL)</li><li>Оптимізація валідаторів</li></ul> |
