# Бонус №1 — автоматичний підрахунок метрик

Після появи workflow в `main` відкрийте **Actions → Lab 10 DORA metrics → Run workflow**, виберіть `main` і задайте межі періоду в UTC. Значення за замовчуванням відтворюють вибірку Лаб 10. Після успішного запуску завантажте `lab10-dora-metrics` у розділі **Artifacts**. Архів містить файл `lab10-automated-metrics.json`.

Ту саму дію можна запустити з GitHub CLI:

```sh
gh workflow run dora-metrics.yml --ref main -f from_utc=2026-10-23T00:00:00Z -f to_utc=2026-11-13T00:00:00Z
```

## Локальне відтворення

Запустіть команду з кореня репозиторію, використовуючи Python 3.12 та авторизований GitHub CLI.

```sh
python -X utf8 scripts/ci_metrics.py --repo ukma-fin-ssdm-2026/YourPathUkma --workflow ci.yaml --from 2026-10-23T00:00:00Z --to 2026-11-13T00:00:00Z --output - > docs/ci-cd/lab10-automated-metrics.json
```

Параметр `--output -` виводить JSON у stdout. Шлях для збереження задається перенаправленням оболонки.

Підрахунок охоплює завершені запуски після push у `main`, створені в заданому вікні UTC з виключеною верхньою межею. Перша версія ручного звіту вимірювала час виконання змін для 80 зелених запусків із PR. Поточний скрипт охоплює 82 зміни зі злитих PR, включно з двома доставленими після невдалого CI, і вісім прямих комітів; для прямих комітів відлік починається з часу авторства. У JSON наведено всі чотири метрики, тривалості в секундах і частки черги та виконання.

## Методика доставки й часток часу

Час змін рахується для кожного унікального SHA, включно з невдалим CI: до найранішого зеленого завершення, яке містить цей SHA. Спорідненість перевіряється GitHub Compare API (`ahead` / `identical`), а не лише порядком запусків. Повторні спроби SHA не дублюють зміну. Якщо доставку в межах вибірки не знайдено, SHA входить у `undelivered_change_shas`; пошук за кінцем вікна не виконується. Частота розгортань, збоїв і відновлення зберігає визначення за завершеними запусками CI.

Для зміни об’єднуються часові інтервали запусків її SHA та першого зеленого запуску доставки, обрізані на момент доставки. Виконання має пріоритет перед чергою при перекритті. `other_seconds` — залишок часу поза цими інтервалами CI. Один зелений запуск може входити до інтервалів кількох змін. Це зважені частки часу змін, не сумарний час раннера. API збирає поточну спробу запуску; для історичної вибірки всі спроби мають `attempt=1`.

У `lead_time_changes` для кожного SHA наведено PR, ID вихідного запуску, ID зеленого запуску доставки та розклад часу. Поточний результат містить 90 інтервалів: до 88 змін додано PR #210 і #211; для PR #154 і #250 доставка відбулася раніше завершення власного CI.

Оновлений JSON сформовано локально з `evidence/lab10-main-ci.json` і перевірок предків Git. Списки батьківських SHA збережено в доказах. Безмережеве відтворення всіх агрегатів і зіставлення із JSON виконується регресійним тестом:

```sh
python -m pytest tests/test_ci_metrics_script.py -q
```

Новий збір GitHub API та запуск workflow після виправлення ще не виконувалися; історичний артефакт workflow у звіті містить попередні значення.
