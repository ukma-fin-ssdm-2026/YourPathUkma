# AGENTS.md — YourPathUkma

Цей файл — контекст для AI-агентів (Claude Code, Copilot тощо), що працюють над кодовою базою проєкту. Тут — стисла, структурована витяжка з повної документації: домен, правила, стек, use-case'и. Ціль: агент має зрозуміти проєкт без читання всього ТЗ.

## 1. Що це за проєкт

Вебплатформа для студентів Факультету інформатики НаУКМА (розширювана на інші факультети) для побудови індивідуального навчального плану:
- вибір вибіркових дисциплін по триместрах,
- контроль кредитного навантаження (240 кредитів / 4 роки),
- AI-рекомендації дисциплін на основі напрямків розвитку студента.

Нормативні дисципліни повністю визначає деканат — вони НЕ обираються в конструкторі, лише відображаються.

Вхід — через корпоративну пошту (Google Workspace SSO).

## 2. Технологічний стек

| Шар | Технологія | Примітка |
|---|---|---|
| Frontend | React + TypeScript, Tailwind CSS | drag-and-drop конструктор плану, фільтри каталогу |
| Backend (основний) | Python, FastAPI | бізнес-логіка плану, особистий кабінет |
| Парсинг САЗ | Python (BeautifulSoup/Scrapy або Playwright, якщо потрібен рендер JS) | запуск вручну адміном або по cron (Background Task); пише в чергу на модерацію |
| БД | PostgreSQL | реляційна модель, зв'язки many-to-many |
| AI-модуль | LLM через API | генерує план + пояснення + альтернативи (адаптер у моноліті) |
| Auth | OAuth2 / Google Workspace SSO | корпоративна пошта НаУКМА |
| Інфра | Docker, GitHub Actions CI/CD | хостинг: Render/Railway (MVP) або сервер університету |
| API | REST | GraphQL — тільки якщо каталог/фільтри суттєво ускладняться |

**Стек ще може коригуватись** — перевіряй з людиною перед великими архітектурними рішеннями.

### Архітектура (Модульний моноліт — ADR-001)
Застосунок розгортається за схемою **модульного моноліту** на базі FastAPI в єдиному Docker-контейнері (ADR-001). Функціонал розділено на три внутрішні логічні модулі (пакети) у спільному процесі:
1. **Core / Planning Module** — бізнес-логіка створення та валідації плану, особистий кабінет, REST API.
2. **SAZ Parser Module** — асинхронні фонові задачі (Background Tasks / Cron) для парсингу САЗ та сертифікатів, що поповнюють чергу модерації.
3. **Recommendation Module (AI)** — адаптер для формування анонімізованих промптів та взаємодії з зовнішнім LLM API (із read-only доступом до даних каталогу).

Такий поділ забезпечує ізоляцію доменів у коді без інфраструктурного ускладнення мікросервісами.

## 3. Доменна модель (ключові сутності)

- **Student** — email, курс, спеціальність, історія планів, лічильник кредитів (використано/залишилось), кредити вільного вибору (ліміт 25).
- **IndividualPlan** — рік, статус (чернетка / подано / очікує деканату / затверджено-синхронізовано), дисципліни по триместрах, рівень навантаження по триместрах, сумарні кредити, посилання на документ деканату.
- **DeaneryPlanDocument** — рік, перелік нормативних дисциплін студента на рік (з розпізнаного документа) — для перевірки конфліктів.
- **Discipline** — назва, опис, тип (нормативна/вибіркова), викладач, рекомендований рік, триместр, кредити, профорієнтовність (напрямок/спеціальність).
- **Instructor** — ім'я, перелік дисциплін.
- **Direction** — напрямок розвитку (Data Science, Cybersecurity...), пов'язані дисципліни.
- **CertificateProgram** — назва, джерело (зовнішній сайт), перелік дисциплін (сирі назви), статус звірки з САЗ по кожній дисципліні.
- **LoadLevel** — низьке/середнє/високе, діапазон кредитів/годин.
- **PlanAlternative** — резервний набір дисциплін на випадок відмови в записі.
- **SyncJob** — дата, ким запущено, статус, к-сть оновлених/доданих дисциплін (окремо для САЗ і для сайту сертифікатів).
- **Admin** — керує запуском парсингу й довідниками (напрямки, сертифікатні програми).

## 4. Бізнес-правила (важливо для валідації/логіки, не тільки для UI)

### Навантаження
- Разом за програму: **240 кредитів за 4 роки** (орієнтир — 60/рік, нерівномірність допустима).
- Рівні тижневого навантаження:
  - високе: 23–25 год/тиждень (макс. 25);
  - середнє: ~20–23 год/тиждень;
  - низьке: <18–20 год/тиждень, але має зберігатись мінімум 57–60 кредитів/рік сумарно.
- Студент обирає рівень навантаження на кожен триместр окремо.
- Якщо обрано низьке навантаження і рік все одно "влазить" у 57–60 кредитів — показати попередження, що навантаження наступних років зросте.
- **1 курс**: план формує деканат, студент участі не бере, плану в застосунку немає.
- **2–3 курс**: студент сам обирає навантаження на кожен триместр (осінь/весна/літо) незалежно.
- **4 курс**: вибір навантаження вимкнено — рахується автоматично з решти кредитів.
- Дозволено обрати лише профорієнтовні (без вільного вибору), але **заборонено** обрати лише вільний вибір без профорієнтовних.

### Дисципліни
- Тип: нормативна (з деканату, не обирається) / вибіркова (обирається).
- Профорієнтовність прив'язана до конкретного напрямку/спеціальності.
- Якщо дисципліна не профорієнтовна для напрямку студента — її можна взяти як **вільний вибір**, ліміт **25 кредитів сумарно за всі 4 роки**.
- Дані про дисципліни надходять із САЗ парсингом (запуск вручну адміном).

### Документ деканату
- Перед побудовою плану на рік студент завантажує документ від деканату (нормативні дисципліни на рік).
- Це потрібно щоб:
  - показати повну картину (вибіркові + нормативні разом);
  - не дати обрати дисципліну, на яку вже записав деканат;
  - врахувати зв'язок з дисциплінами з попередніх років (беруться з "Індивідуального плану").

### Напрямки та сертифікати
- До **3 напрямків розвитку** на студента.
- Якщо студент відмічає інтерес до сертифіката:
  - парситься окремий сайт сертифікатних програм;
  - кожна дисципліна зі списку звіряється з каталогом САЗ **без урахування регістру** та подібних розбіжностей;
  - якщо хоч однієї дисципліни немає на САЗ → сертифікатна програма **недоступна цього року**;
  - якщо доступна й відповідає напрямку — пропонується включити в план;
  - якщо окрема дисципліна входить у сертифікат (без повного набору) — повідомлення "ця дисципліна входить у сертифікат X, додати / дізнатись більше".

### Відгуки про дисципліни
- Платформа **не** зберігає й не показує відгуки — це зовнішній сервіс.
- Під згенерованим планом лише посилання: "Почитати відгуки: [лінк]".

## 5. AI-рекомендації (специфіка для агента, що працюватиме з LLM-модулем)

Вхід моделі: опис дисципліни з каталогу, обрані напрямки, побажання студента (небажані/бажані викладачі, навантаження, інтерес до сертифіката), історія власних минулих планів студента.

**Критично**: дані інших студентів (плани, відгуки, досвід) модель НЕ отримує і НЕ використовує.

Вихід: перелік вибіркових дисциплін на кожен триместр + коротке пояснення для кожної, чому вона корисна. Той самий (або окремий) прохід генерує 2–3 альтернативні варіанти на випадок недоступності основної дисципліни при записі.

## 7. Особистий кабінет — структура екранів

- **Профіль студента**: курс, лічильники кредитів (…/240, …/25 вільний вибір, …/54 профорієнтовні).
- **"Науковий шлях"** (3 під-вкладки):
  - **Індивідуальний план** — усі плани за роки навчання + кнопка "Оновити" (підтягує затверджений деканатом варіант з САЗ).
  - **Збережені плани** — лише ті, що студент явно зберіг.
  - **Створити план** — конструктор: вибір дисциплін, побажання, AI-генерація, альтернативи; звідси план можна зберегти → потрапляє у "Збережені плани".

## 8. Дорожня карта (для пріоритизації задач агентом)

**MVP:**
- Ручний/напівавтоматичний парсинг САЗ.
- Кабінет: перегляд планів + лічильник кредитів.
- Конструктор плану з перевіркою обмежень (кредити/навантаження/триместр), без AI.
- Проста фільтрація каталогу (напрямок/викладач/триместр).

**Другий етап:**
- AI-побудова плану з поясненнями (без даних інших студентів).
- Генерація альтернативних варіантів (топ-3 запасні на слот).
- Парсинг і звірка сертифікатних програм.

**Третій етап:**
- Автоматизація регулярного парсингу САЗ з модерацією.
- Розширення на інші факультети (узагальнення "напрямок"/"сертифікатна програма").
- Аналітика для деканату.

## 9. Обов'язкові правила для агента (ЗАВЖДИ виконувати)

- **Кожен артефакт** (код, документ, конфіг, згенерований текст тощо), який агент створює або суттєво змінює, **має містити нотатку «Використання ШІ»**: що саме створено/змінено за допомогою ШІ, і як це перевірено (тести, ручний рев'ю, лінтер тощо). Без цієї нотатки артефакт вважається неготовим.
  - Для коду — коментар/секцію на початку файлу або в PR-описі.
  - Для документів — окремий розділ наприкінці файлу.
  - Пропускати цей крок не можна, навіть для дрібних правок.

## 10. Нотатки для агента

- Нормативні дисципліни — **read-only** дані з документа деканату, ніколи не редагуються студентом у конструкторі.
- Будь-яка перевірка лімітів (240, 25, 57–60 кредитів) — це серверна валідація, не лише UI-підказка.
- Звірка назв дисциплін для сертифікатних програм — **case-insensitive** порівняння (і стійке до подібних розбіжностей у написанні).
- AI/ML-модуль функціонує в межах моноліту з read-only доступом до спільної бази даних.
- Парсинг САЗ і парсинг сайту сертифікатів — окремі, незалежно запускані фонові джоби (`SyncJob`).
